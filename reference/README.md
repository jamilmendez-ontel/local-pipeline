# local-pipeline reference samples

Sample/reference files provided by the user, kept locally for understanding.
The data/binary files are gitignored (see `.gitignore`); this README is the
committed, portable record of what each one is.

## email-samples/

### `user_priorities_success.eml`
- **Purpose:** Reference for the User Priorities pipeline status email, captured
  to confirm exactly what the SUCCESS notification looks like before we stopped
  sending it (see below).
- **Source:** Forwarded by Jamil from his inbox, 2026-06-22 (original run
  2026-06-22 00:25:56 EDT, 1m 20s).
- **Sender / recipients:** From `jamil.mendez@nanoninth.com` (the Apps Script
  notifier account) to `jamil.mendez@ontel.co, hajie@ontel.co, sheena@ontel.co`.
- **Subject:** `Pipeline SUCCESS: User Priorities (1m 20s)`
- **Shape:** `multipart/mixed` — a `multipart/alternative` body (plain + HTML)
  plus one base64 `.txt` log attachment (`pipeline_log_<ts>.txt`).
- **Body content:** green `#2e7d32` SUCCESS header; Started/Ended/Duration; a
  "Pipeline Details" table (name/status/duration/details/error); a "Row Counts"
  table grouped by layer — Raw `raw_user_priorities` and Staging
  `stg_user_priorities`, before/after/change (this run: 11,769 → 11,781, +12).
- **Generated by:** `swift_api_pipeline/pipeline_notifier.py`
  (`_build_html_email` / `send_pipeline_email`); recipients are
  `NOTIFICATION_RECIPIENTS` in that file.

#### Why it's kept
On 2026-06-22 the User Priorities pipeline moved to a high-frequency schedule
(every 10 min, later 5 min — DB refresh only, via the Apps Script
`triggerPriorities` dispatch with `run_export=false`). To avoid a SUCCESS email
every 10 minutes, the workflow now emails **only on failure**:
`main.py --pipeline user_priorities` runs the first attempt with `--no-email`
and the retry with `--email-on-failure-only`. The FAILED email uses the same
template as this sample but with the red `#c62828` header and the error/log
attachment. This `.eml` documents the SUCCESS format that is no longer sent.
